## 정리 대상 1 — UAT 복제 프로젝트 행 (sc_projects)

패턴: `beac0005-0000-4000-8000-0000000000NN`
- 사용된 NN: 01~03 (초기), 11 (UAT-01 링크 복구), 21~23 (hotfix2), 31~33 (RC2 1차),
  34~36 (2차), 37~39 (3차), 41~43 (4차), 44~46 (5차/최종)
- 처리: **최종 세트(44~46)는 대표 육안 확인이 끝날 때까지 유지**, 나머지는 삭제 후보.
- 삭제 SQL (승인 후):
  `delete from sc_projects where id::text like 'beac0005-%' and id::text not like '%44' and id::text not like '%45' and id::text not like '%46';`

## 정리 대상 2 — 스토리지 출력물 (videos-clips)

- `{uid}/wm_v32_beac0005-…NN.mp4` — 복제 재처리 출력 (NN 위와 동일 기준)
- `wmtmp-v32/beac0005-…NN/*` — 중간 산출물 (plan.json, seg_*.mp4, work.mp4)
  ※ wmtmp는 24h TTL 정리가 있다면 자동 소멸 — 수동 삭제 불필요 여부 확인 후 진행
- 골든 출력 `{uid}/wm_v32_beac0002-…NN.mp4` — 최신 1세트만 유지, 이전 실행분 삭제 후보

## 정리 대상 3 — 사이트 "내 작업" 목록 노출

복제 행이 status='wm_done'으로 보이므로 대표 화면에 [v32-UAT*] 행이 나열됨.
행 삭제(정리 대상 1)로 함께 사라짐. 대표가 결과 확인용으로 쓰는 동안은 유지.

## 실행 절차 (승인 후)

1. 대표 승인 확인 (이 문서 기준으로 "정리 진행" 답변)
2. 최종 세트(44~46) 제외 여부 재확인
3. SQL로 행 삭제 → 스토리지 객체 삭제 (prefix 목록 조회 → batch delete)
4. 삭제 결과 카운트 보고 (행 N개 / 객체 M개)
