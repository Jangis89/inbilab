## 밝혀진 사실 (측정으로 확정)
1. "업로드 85초"의 실체 = 출력 프레임 검증(전체 해독) ~50s + 단일 PUT 320MB ~30s.
   - 검증을 패킷 카운트(해독 없음, 0.3s)로 교체 — mp4 H.264는 패킷=프레임, 실패 시 기존 방식 자동 폴백
   - 업로드는 S3 멀티파트 16MB×8동시 (357MB 실측 22s→5.9s, 4배), checksum 재다운로드 대조 통과
2. "source download 78초"의 실체 = 다운로드 ~13s + 프레임 카운트(해독) ~50s + probe.
   - 다운로드: Range 병렬 8스레드 (357MB 13.2→3.5s) / 카운트: 패킷 방식 0.6s
   - 참고: 기준 원본은 자가복구 과정에서 357MB 원본화질본으로 복원되어 있었음 (프레임 수·내용 동일)
3. 출력 파일은 320MB (crf18) — S3 업로드 6~10s로 처리.
